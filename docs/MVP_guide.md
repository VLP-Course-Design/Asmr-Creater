先把这个系统扒到底层再谈功能。它的本质就是一条**单向映射链**:

> 一张图 → 视觉特征 → 一份结构化中间表示(JSON) → 音频控制参数 → 一路混好的声音流

PDF 里所有花哨的东西(开放词汇、深度衰减、人声旁白、情感分析、马尔可夫状态机)全都是挂在这条链上的**可插拔模块**。MVP 唯一要证明的事情只有一件:让这条链端到端跑通,并且让人一听就觉得"这声音确实是从这张图里长出来的"。只要这个核心闭环成立,后面所有模块都是往上加料。

还要先点破一个关键张力,它直接决定 MVP 的骨架:

- **PDF 的调性**是"轻量化 / 端侧 / YOLO + DSP",追求 CPU 上实时。
- **课设的硬性要求**是"用视觉语言大模型给所有图片生成多维度描述 + prompt engineering",这是评分点,不做会直接丢分。

这两者不冲突,但结论是 MVP 的职责必须这样切分:**VLM 负责「理解与氛围」(课程要求 + 给白噪音注入灵魂),YOLO/几何负责「定位与空间」,DSP 负责「发声」。** VLM 那一步既是课程评分点,又恰好是决定"底噪基调 + 会不会突然响起猫叫"的灵魂步骤,一步两用。

还有一个容易忽略的点:这个项目其实有**两种运行模式**,MVP 都要覆盖,而且它们共用同一套视觉层逻辑:

1. **离线批处理模式**(课程刚需):把 2000 + 369 张图全部过一遍 VLM,产出一份结构化描述数据集 —— 这本身就是一个交付物,也是评估的基础。
2. **在线 Demo 模式**:用户传一张图 → 实时跑通管线 → 出声音。这是答辩视频里最出彩的部分。

## 一、MVP 功能清单(尽量全,但划清边界)

**MVP 内(必须做,缺一个核心闭环就不完整):**

- 支持上传/选择单张图片作为输入。
- 视觉层能对该图输出一份干净的结构化 JSON(全局氛围 + 若干实体 + 每个实体的左右位置)。
- 用 VLM + 精心设计的 prompt,为整个数据集批量生成多维度描述,并落盘成结构化文件(直接满足课程要求)。
- 音频层能根据全局氛围,用 DSP 实时生成无缝循环的底噪(粉红/棕色/白噪音,音量和滤波随明暗变化)。
- 至少 5~8 类常见物体能触发对应的离散音效(翻书、瓷杯、键盘、鸟鸣、猫呼噜、开窗/风、水声…),从本地素材库加载。
- 基础 2D 声像平移:物体在画面左边,声音就偏左耳。这是"从播放器升级成空间音频引擎"的最小可感知增量,成本极低,效果极明显,一定要进 MVP。
- 一个极简 Web UI:上传图 → 显示识别结果 → 播放/暂停 → 每条音轨一个音量滑块可手动微调。
- 一份基础评估(见第四部分)。

**MVP 外(架构上留好接口,以后再加):**

- UI 文字输入框 → 开放词汇检测 / 声景 DIY(YOLO-World / Grounding DINO)。
- 基于单目深度(Depth Anything V2)的距离衰减 + 低通 + 混响。
- TTS/AI 人声场景旁白、空灵哼唱、Walla 人声。
- 情感分析、马尔可夫状态机的概率化随机触发。
- OpenAL/HRTF 专业 3D 空间音频。
- 抽象画/古典艺术/医学影像的跨域迁移测试(这个建议留作报告里的"迁移能力讨论",工作量小、加分高,可以放在 MVP 完成后顺手做)。

一个战略建议:把这些"MVP 外"的模块在报告里全部写成**已规划的可插拔扩展 + 引用 ImageBind/Soundify/Diff-Foley 做理论背书**,即使没全实现,也能把项目的学术厚度撑起来。PDF 后半段那份论文清单直接用。

## 二、宏观层面:实现路径与里程碑

我会把它拆成 5 个阶段。这里有一个**最重要的工程决定,必须放在最前面:先定死视觉层和音频层之间的 JSON 契约(接口先行)。** 一旦这份 schema 定下来,两个组就能完全并行开发、各自 mock 对方的输入,还能随意替换底层模型不互相影响。这是整个项目能不能按时做完的关键。

- **阶段 0 · 地基**:探数据集、选 VLM、设计并迭代 prompt、**敲定 JSON schema**、搭好素材库目录规范。产出:能跑通的批量描述脚本 + 一份 schema 文档。
- **阶段 1 · 视觉层**:单图 → 干净 JSON。先只做全局氛围 + YOLO 检测 + X 坐标,先不碰深度。
- **阶段 2 · 音频层**:纯靠一份手写的 mock JSON,把 DSP 底噪 + 素材触发 + 声像平移 + 混流跑通。这一步完全不依赖视觉层,可与阶段 1 并行。
- **阶段 3 · 集成 + UI**:接上真实 JSON,做 Web 界面,反复调"图-声匹配感"。
- **阶段 4 · 评估 + 报告 + 演示视频**:批量结果评估、消融、录 demo。

## 三、详细层面:各模块具体要做什么

### 0. 先敲定 JSON 契约(最优先)

整个项目最该先做的一件事,就是把这份中间格式定死。PDF 里那个 schema 太简单,建议扩成下面这种,把音频层需要的所有维度一次给全:

```json
{
  "global_vibe": {
    "scene_type": "bedroom",        // VLM 输出的场景标签
    "mood": "calm",                 // 氛围词:宁静/喧闹/压抑/温馨
    "brightness": 0.28,             // 0~1,决定底噪类型和音量
    "warmth": "cool",               // 冷/暖,影响滤波
    "base_noise": "brown",          // 建议底噪:white/pink/brown
    "time_of_day": "night"
  },
  "entities": [
    {"name": "cat", "state": "sleeping", "x": 0.22, "depth": "near", "conf": 0.91},
    {"name": "window", "state": "rainy", "x": 0.80, "depth": "far", "conf": 0.75}
  ]
}
```

`x` 用归一化坐标(0=最左,1=最右),`depth` MVP 阶段可以先用"边界框面积大小"粗略估(框大=近),深度模型留到以后。`state` 字段是关键,它承接了 PDF 里"睡觉的猫→呼噜声"那个亮点——但这个字段主要靠 VLM 填,不是 YOLO。

### 1. 视觉层要做的事

**步骤 1 · 图像预处理。** 用 Pillow 统一读入、转 RGB、resize 到 VLM/YOLO 各自要的尺寸。工作量很小,但要写成能批处理整个数据集的循环(为课程的"给 2000 张图批量生成描述"服务)。

**步骤 2 · 全局氛围(VLM,课程评分核心)。** 这一步决定项目分数下限。要做的是:选一个免费 VLM(本地量化版 Qwen2-VL-2B/Qwen2.5-VL,或走免费 API 如智谱 GLM-4V、通义千问-VL 的免费额度),然后**设计一个能一次性吐出结构化多维度描述的 prompt**。关键技巧:

- 要求模型**直接输出 JSON**,字段固定为上面 schema 里的 `global_vibe`,别让它写散文再解析。
- 用 few-shot 给 1~2 个示例,锁定输出格式和取值范围(如 mood 只能从给定词表选)。
- 让它顺便列出画面里"有发声潜力"的物体清单 + 各自状态,喂给下游当候选。
- 这份 prompt 本身、迭代过程、以及"不同 prompt 对描述质量的影响"就是报告里 prompt engineering 那一节的主体,一定要留好版本记录。

**步骤 3 · 局部实体检测(定位)。** MVP 用 YOLOv10/v11-Nano 拿 COCO 80 类 + Bounding Box 就够,CPU 也能跑。开放词汇(YOLO-World / Grounding DINO)先不做,但代码里把"检测器"抽象成一个可替换接口,以后换开放词汇只改一个类。VLM 给的物体清单和 YOLO 的检测框可以做个简单融合:YOLO 认得的用框(有坐标),YOLO 认不得但 VLM 提到的(如"香薰机")先记下来,留给未来的开放词汇分支。

**步骤 4 · 空间坐标映射。** 只做两件事:算每个框中心点的归一化 X;用框面积估远近。产出填进 JSON 的 `x` 和 `depth`。深度模型(Depth Anything V2)是 MVP 外。

**步骤 5 · 结构化输出。** 把上面全拼成那份 JSON,校验字段完整性后抛给音频层。视觉层到此为止,绝不碰任何音频代码——这是解耦的纪律。

### 2. 音频合成层要做的事

**步骤 1 · 参数解析。** 写一个 mapper,把 JSON 翻译成音频控制参数。MVP 用连续线性映射就好(比 if-else 高级、比状态机简单):比如 `brightness` 归一化后线性控制底噪音量和低通截止频率,画面越暗→底噪越低沉、音量越小。马尔可夫状态机(下雨概率触发雷声)留到以后。

**步骤 2 · 底噪生成。** 强烈按 PDF 建议用 `pyo` 的 DSP 实时生成(`BrownNoise()/PinkNoise()`),两行代码、体积几 KB、永不循环、音质好,还能挂滤波器动态调音色。别用 MP3 循环那套。这是"底噪即灵魂"的技术支撑。

**步骤 3 · 离散音效触发。** 建立一张 `检测标签 → 素材文件` 的映射表(这张表就是系统的"内容",见下一节)。检测到什么就从素材库随机抽一个变体播放。MVP 先做确定性触发(检测到就播),概率化留到以后。

**步骤 4 · 空间渲染。** MVP 只做恒定功率的 2D 声像平移:根据 JSON 里的 `x` 算左右声道增益。这是投入产出比最高的一步。基于深度的低通+混响(伪 3D)是加分项,可留到集成完成后有余力再加。

**步骤 5 · 多轨混流。** 把底噪 + 各离散音效按声道相加成一路双声道流输出。用 `pyo` 的 Server 直接接管声卡最省心。MVP 里能同时播底噪 + 2~3 个平移后的音效就达标。

关键提醒:音频层从第一天起就应该靠**手写的 mock JSON** 独立开发,完全不等视觉层。这样两条线真正并行,最后集成只是把 mock 换成真 JSON。

### 3. 素材库要怎么整理

素材库不是"下载一堆 wav 就完事",它是需要专门维护的一等交付物,而且**版权要能写进报告**。建议:

**目录结构**按用途分两类:
```
sounds/
  ambient/     # 长循环底噪备用:rain / forest / cafe / ocean / city
  triggers/    # 短音效,按检测标签命名
    cat/  cat_purr_1.wav  cat_meow_1.wav   # 每类 3~5 个变体
    cup/  book/  keyboard/  bird/  window/ ...
```

变体池(每个物体 3~5 个微小变体,`random.choice` 抽取)是提升真实感的低成本手段,PDF 里提到了,值得做进 MVP。

**一张元数据表**(CSV/JSON),给每个文件记:标签、时长、是否可循环、默认音量、许可协议、来源 URL。报告里"数据/素材来源"和版权说明直接用它生成。

**素材来源**优先 CC0/免版税:Freesound(搜关键词时左侧筛 CC0)、Pixabay、BBC Sound Effects(教育用途)、Adobe Audition 免费包、Zapsplat(人声细分)。别去百度搜"音效下载"。人声/旁白/TTS 全部划到 MVP 外。

**那张映射表**(标签→素材)是真正的手工活,也是最容易被低估的工作量。COCO 80 类里真正常在生活场景出现、又有意义的其实就一二十类,先把这一二十类的映射和素材备齐,就够 demo 惊艳了。

### 4. UI 与集成(MVP 最小界面)

一个 Web 页面即可(Gradio 最快,或简单 Flask + 前端)。要素:图片上传/选择框、显示识别结果(标签 + 框)、一个播放/暂停按钮、每条音轨一个音量滑块(对应 PDF 里"保留可自行调整各音效")。文字 prompt 输入框(开放词汇/DIY)在界面上留位置但先禁用,标注"未来功能"。注意:`pyo` 是本地音频服务器,如果要做成纯网页在线播放,可能需要把合成结果渲染成一段 wav 再传给前端播放,这条工程路径要早点验证。

### 5. 评估与讨论(课程要求,别漏)

音频系统难量化,建议三条腿:

- **VLM 描述质量**:在验证集抽 30~50 张,人工按维度覆盖度/准确度打分,或用一个更强的 VLM 当 judge 做交叉评审;这直接回应"生成结果评估"。
- **视觉→音频匹配感**:做主观听测(几个同学 A/B 盲听,你们系统 vs 随机映射 baseline,打 1~5 分),这是最能说服人的证据。
- **检测准确率**:手工标注一个小子集,报 YOLO 的命中率 + VLM 场景分类的对错。
- **迁移讨论**(加分):拿抽象画/古典画/医学影像各几张跑一遍,看 VLM 描述和音效映射如何崩掉或有趣,写进"不同领域表现"讨论。工作量小、加分高。

## 一句话总结与并行分工建议

MVP 的最小充分闭环 = **一张图 → VLM 出氛围+YOLO 出坐标 → JSON → pyo 底噪 + 素材触发 + 声像平移 → 可调音量的网页播放**,外加**全数据集的批量 VLM 描述**满足课程刚需。三条线可并行:视觉线(VLM prompt + YOLO)、音频线(靠 mock JSON 独立开发 DSP)、素材线(整理素材库 + 映射表);集成期再合流,把剩余精力投在"调匹配感"和评估上。
