# ASMR视觉锚点词典与检测边界

**版本：** 1.0  
**对应视觉记录：** schema 2.3  
**锚点总数：** 87  
**对应声音语义：** 66个受控 `sound_id`

## 1. 视觉锚点是什么

视觉锚点是图片中“可以支持某种助眠声音联想”的可观察证据。它不表示声音正在真实发生，也不直接决定音量、概率、素材文件或HRTF参数。

例如：

```text
visible_bird（可见鸟）
  → 支持 bird_chirp 候选
  → 决策层再结合场景、安全等级和层数预算决定是否播放
```

锚点必须来自本词典，不得输出自由文本近义词。检测模型看不清或不满足定义时应不输出，而不是选择最接近的类别。

## 2. 锚点空间类型

| 类型 | 含义 | 边界框与空间音频处理 |
|---|---|---|
| `point_object` | 可定位的单个物体或小型声源 | 框应贴合对象；可用于左右位置，深度可靠时可用于HRTF距离 |
| `action` | 可定位的动作或交互 | 框应覆盖动作参与者和关键物体；可用于局部声源定位 |
| `group_object` | 多个同类对象或群体 | 框覆盖主要群体；适合扩散声源，不宜作为极窄点声源 |
| `region_context` | 大面积环境、天气或视觉条件 | 框覆盖证据区域；只用于候选和环境床，不使用单框生成点声源HRTF |
| `installation` | 固定设备或大型设施 | 框贴合设备；只有明确运行证据时才使用 `running/operating` 类锚点 |

### 2.1 通用检测规则

- 同一视觉证据不得同时输出互为强弱版本的重复框。例如已输出 `hands_on_keyboard_typing` 时，通常无需再为同一键盘输出 `visible_keyboard`。
- 动作锚点优先于静态物体锚点；强证据优先于弱证据。
- 边界框必须基于修正EXIF方向后的原图，并归一化到 `[0,1]`。
- `region_context` 的框面积不能用于推断真实距离，也不进入点声源HRTF门控。
- 单张图片不能证明真实声音正在发生；`confidence` 只表示视觉检测可信度。
- 普通人物、普通房间和与声音无关的物体不属于本词表。

## 4. 强弱锚点的使用边界

| 强度 | 含义 | 决策层建议 |
|---|---|---|
| 强 | 视觉证据与声音语义直接对应 | 可以进入候选，但仍受助眠安全、素材和层数限制 |
| 中 | 存在合理声音联想，但不能证明声音正在发生 | 降低触发概率或以较轻连续层使用 |
| 弱 | 只有环境或静态物体联想 | 默认不播放或极低概率；不能独立提高音量 |

同一锚点即使是“强”，也不代表必定发声。例如 `visible_bird` 只能说明鸟鸣是合理候选，不能证明照片拍摄瞬间鸟正在鸣叫。

## 5. 深度与HRTF注意事项

- `point_object`、`action`：最适合使用框中心和可靠 `depth_hint` 生成局部HRTF位置。
- `group_object`：应增加声源宽度或从组内选择少量位置，不得把整个人群压缩成极窄点声源。
- `region_context`：一般生成宽环境床，不按框中心生成鸟点式HRTF。
- `installation`：固定设备可定位，但不应添加无视觉依据的明显空间运动。
- 只有参与播放的可空间化锚点全部通过深度不确定性门控时，才使用双耳空间计划；否则按既定规则统一退化为单声道。
- 边界框大小只在存在该锚点的尺寸先验时作为轻微距离修正，不能直接换算真实米数或音量。

## 6. 数据集生成建议

1. 先检测强证据动作和实体，再检测中、弱环境证据。
2. 同一声音只保留信息量最高的锚点，例如翻页动作优先于打开的书。
3. 运行IoU去重并合并同义证据，不在Schema中硬编码锚点数量上限。
4. 生成阶段的最大数量、置信度阈值、去重阈值和优先级写入 `anchor_selection_config_version`。
5. 对弱锚点单独统计命中率和人工误报率；若某弱锚点长期不能改善声音选择，应从下一版词表移除。
6. 抽样可视化所有类别的框，特别检查动作框、区域框和EXIF方向。
